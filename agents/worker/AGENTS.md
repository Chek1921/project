# Воркер и очередь

Файлы: `worker/queue.py`, `worker/processor.py`, `worker/run.py`, `worker/external.py`.

- В проде четыре экземпляра воркера и SQLite — критична межпроцессная атомарность.
- `claim_next` сейчас выбирает и обновляет задачу разными SQL-операциями: проверять
  гонки, а не только одиночный сценарий.
- Сохранение score и перевод задачи в `done` выполняются разными транзакциями;
  учитывать окно сбоя между ними.
- Внешний API допускает сбои и возвращает нестандартные тела. Не убирать обработку
  `null`, cp1251 и повторную попытку без теста.
- `processing`-задачи не возвращаются в очередь после смерти воркера.
